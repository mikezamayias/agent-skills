# Sync Context

The idea comes from tip 4 in [Boris Cherny's Claude Code team tips](https://x.com/bcherny/status/2017742741636321619): a command that syncs the last 7 days of work tools into one context dump.

You have been invoked to aggregate recent context from connected services and produce a morning briefing.

## Process

Run the following in parallel using subagents:

### Agent A — GitHub (via `gh` CLI)

```text
gh pr list --author @me --state all --limit 10 --json number,title,state,updatedAt,url
gh pr list --reviewer @me --state open --limit 10 --json number,title,state,updatedAt,url
gh issue list --assignee @me --state open --limit 10 --json number,title,labels,updatedAt,url
gh search issues --involves @me --created=">$(date -v-7d +%Y-%m-%d)" --json number,title,repository,updatedAt --limit 20
```

Summarize: open PRs needing review, PRs I authored that have reviews, open issues assigned to me.

### Agent B — Slack (via `slack` skill if available)

If the `slack` skill is available:

- Pull recent threads from the last 2–3 days in relevant channels
- Summarize: unread threads, mentions, action items

If Slack is not configured: skip and note "Slack not configured — run /slack setup"

### Agent C — PostHog (via MCP)

```text
mcp__posthog__query-run with HogQL:
  SELECT event, count() as cnt, max(timestamp) as last_seen
  FROM events
  WHERE timestamp > now() - INTERVAL 7 DAY
    AND event LIKE '%error%'
  GROUP BY event
  ORDER BY cnt DESC
  LIMIT 20
```

Summarize: top errors, spike patterns, anything new in the last 24h vs 7-day baseline.

## Output

Write to `~/.claude/context-dump.md`:

```markdown
# Context Dump — [DATE TIME]

## GitHub

### PRs Needing My Attention

- [#N] title — state (updated X ago) [url]

### My Open Issues

- [#N] title — labels (updated X ago) [url]

## Slack

[summary or "not configured"]

## PostHog — Recent Errors

| Error | Count (7d) | Last Seen |
| ----- | ---------- | --------- |
| ...   | ...        | ...       |

---

## Suggested Focus

Based on the above, the highest-priority items appear to be:

1. [most urgent item]
2. [second most urgent]
3. [third most urgent]

_Generated by /sync-context_
```

## After Writing

1. Display the "Suggested Focus" section directly in chat
2. Ask: "Want me to pull up any of these items in detail?"

## Notes

- Keep the dump fresh — always overwrite `context-dump.md`, don't append
- If a service fails, note it in the output and continue with others
- The goal is a 2-minute brief, not exhaustive data — summarize aggressively
